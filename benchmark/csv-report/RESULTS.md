題材: CSVを列ごとに集計し、Markdownの表で出すコマンド(画面なし、4ファイル構成)。要件文と固定テスト(19件)は、この題材のために新しく書いた。
完成品の置き場: D = `Desktop/ai-bench/D1〜D3`(Claude Code 単体)、C = `projects/bench-c1_… c2_… c3_…`(オーケストラ)。
オーケストラは、タイマー付きメモ帳の測定で直した状態(`mkdir` 許可と、複数行スクリプトの分割修正)で動かした。

## 読み取り
- D2・D3 の不合格は、固定テスト16番(引数の順番を変えても動く)だけ。要件文には引数の順番の自由は書いていないので、テストが要件より厳しかった。16番を除けば、方式による品質差はない。
- オーケストラは、承認が出たのが C1 と C3 の2回。出た承認は、すべて `node --test test/<名前>.test.mjs`(AI が書いたテストファイルの実行)。モジュールごとにテストを書くタスクの文面が、「テストを走らせる作業」の判定に当たらなかったため。
- C3 の使用量が $1.58 と、他の2回の約3〜4倍。承認が出るたびにタスクをやり直す仕組みのため、承認の回数が多いと、使用量も増える(原因の確認は未実施)。
- 小さな題材での傾向であり、題材は1つ。
