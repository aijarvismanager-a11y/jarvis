# 比較測定: タイマー付きメモ帳(Claude Code 単体 vs AI オーケストラ)

目的: 同じ小さなアプリを両方式で3回ずつ作り、効率・能力・品質・過程を比べる。
状態: 要件文とテストは作成済み。**まだ1回も実行していない。**

## ファイル
- `REQUIREMENTS.md` … 両方式へ渡す依頼文(一字も変えない)
- `hidden-tests/core.hidden.test.mjs` … 固定テスト15件。**作る側に見せない・渡さない**(依頼文の「別の人が用意したテスト」がこれ)
- 参照実装で15件すべて通ること、わざと壊した実装で落ちることを確認済み(2026-11-24)

## 実行手順(1回ぶん)
1. 空のフォルダを用意する(事前の記録・CLAUDE.md なし)。方式と回数を決める(A1〜A3 = Claude Code 単体、B1〜B3 = オーケストラ)。
2. `REQUIREMENTS.md` の本文をそのまま渡す。開始時刻を記録する。
   - A: 新しい Claude Code の会話に貼る。
   - B: 新しいプロジェクトに、1つの依頼として貼る。
3. 人の介入は「質問への回答」と「承認」だけ。回数と内容を下の表に記録する。
4. 作る側が「完成」と言ったら終了時刻を記録する。
5. 完成品のフォルダを指定して固定テストを実行する。

```powershell
$env:BENCH_APP_DIR = "<完成品のフォルダ>"
node --test benchmark/timer-memo/hidden-tests/core.hidden.test.mjs
```

6. 実機確認(下の3項目)を、同じ手順で人が行う。
7. 方式が分からない形にして(フォルダ名を A/B ではなく乱数にする)、2人以上で品質を5段階採点する。

## 実機確認(各1点・計3点)
1. `index.html` を開き、メモを追加すると一覧に出る。
2. 削除でき、ページを開き直しても、残したメモが残っている。
3. 1〜2分後の時刻を付けて追加すると、その時刻を過ぎたとき知らせが1回だけ出る(繰り返し出ない)。

- 使用量: A は会話の記録のトークン数、B はアプリの ai_runs の合計。
- 手戻り回数: 一度「完成」としたあとのやり直し、または再計画の回数。

## 結論の出し方(先に決めてある)
- 効率: 実時間の平均と、使用量の中央値で比べる。
- 能力・品質: 固定テスト合格数、実機確認、品質点で比べる。
- 差が10%以内なら「差は測れなかった」と書く。1回だけの差は結論にしない。
- 小さな題材では計画やレビューの準備が不利に働く。結論は「小規模な作業での差」に限る。
