# t13: 遅延再送出(delayed resink)の効果 実機再計測手順

対象: `src/Fence.App/Infrastructure/Win32/DesktopZOrderService.cs`(`t11_code_delayed_resink.md` で実装、`t12_code_review_delayed_resink.md` でレビュー済み)
入力: `t12_code_review_delayed_resink.md`、`TESTLOG.md`
制約: 本書は手順書のみを作成するもので、実機操作そのものは本作業(test工程)では行わない。

## 1. 目的

修正前の実測(Win+D押下後にフェンスがProgmanの後ろに隠れている時間を3回測定した結果: **304ms・158ms・258ms**、t9調査・ユーザー提示の事実)と同じ測り方で、修正後(30/100/250/500ms後の追い打ちSinkAllを追加した版)の隠れ時間を再計測し、0.15〜0.3秒の消失が解消されたかどうかを判定するための手順をまとめる。

自動テストが存在しないため(`docs/status-report.md` 3節に記載の通り、Gageはテストプロジェクトを持たず手動検証のみに依存している)、本計測も実機での目視・録画解析による手動検証となる。

## 2. 事前準備

1. 最新の修正を取り込んだビルドを作る。
   ```
   pwsh -File tools/publish.ps1
   ```
   `publish/win-x64/Gage.exe` が作り直されたことを確認する(**必ずこのスクリプト経由で行う**。`publish/Gage.exe`(旧・フレームワーク依存ビルド)は誰も参照していないため検証対象にしないこと — `docs/status-report.md` 6節の事故例を参照)。
2. 稼働中の旧Gageプロセスを終了し、作り直した `publish/win-x64/Gage.exe` を起動する。
3. デスクトップ上にフェンスが最低1枚以上表示されている状態にする。メモ帳やブラウザなど、通常のアプリケーションウィンドウも1〜2個開いておく(Win+D操作の一般的な使用状況に近づけるため)。
4. `%APPDATA%\Gage\gage.log` を開く準備をしておく(3-3節で使用)。

## 3. 計測方法

### 3-1. 録画の準備

今回の計測対象は0.1〜0.3秒程度の短時間の消失であり、目視だけでは「消えた/消えていない」の判定しかできずミリ秒単位の時間が取れない。前回の304ms・158ms・258msという実測値も、消失区間を時間軸で切り出せる方法で測られたものである(本リポジトリ内には計測専用スクリプトは保存されていないため、本書では以下の録画ベースの方法を採用する)。

1. 画面録画ツールを起動する(Windows標準の Xbox Game Bar: `Win+Alt+R` で開始/停止、または既存の画面録画ソフト)。**フレームレートが分かるもの**(60fpsなど)を使うこと。フレームレートが固定・既知でないと、後述のフレーム数→ミリ秒換算ができない。
2. Gageのフェンスと、デスクトップの他アプリウィンドウが両方映る範囲で録画を開始する。

### 3-2. Win+D押下と録画

1. 録画を開始した状態で `Win + D` を押す。
2. フェンスが隠れて再び前面に戻るまで、2〜3秒ほど録画を継続してから録画を停止する。
3. 同じ条件でこれを**3回**繰り返す(前回計測と回数を合わせる)。1回ごとに `Win + D` をもう一度押して元の表示に戻してから次の計測に進む。

### 3-3. 録画の解析(隠れ時間の算出)

1. 録画した動画を、フレーム単位で送れるプレーヤー(VLCの「次のフレーム」キー操作、または動画編集ソフトのタイムライン)で開く。
2. `Win+D` を押した瞬間(すべての通常ウィンドウが最小化し始めるフレーム)を基準点とする。
3. フェンスの外枠がデスクトップアイコン層の背後に回って**見えなくなった最初のフレーム**と、**再び前面に見えるようになった最初のフレーム**を特定する。
4. (隠れ始めフレーム番号 〜 再表示フレーム番号の差)×`1000 / fps` で、隠れていた時間をミリ秒換算する。
   - 例: 60fpsの録画で9フレーム分隠れていた場合 → 9 × (1000/60) ≒ 150ms。
5. 3回分の値をそれぞれ記録する(前回の記録形式「約XXXms・XXXms・XXXms」に合わせる)。

### 3-4. 補足確認(ZOrderDiagnosticService、任意・裏付け用)

録画解析と併せて、Win+D押下直後の可能な限り早いタイミングでトレイアイコンを右クリック→「Z-order診断をログに書く」を押し、`gage.log` の `[ZOrderDiagnostic]` 行の末尾、`事実1:` が「Gageの枠はすべて、デスクトップのアイコン層(Progman/WorkerW)より前にある」と出ていることを確認する。これは一瞬のスナップショットであり隠れ時間そのものは測れないが、録画解析の結果と矛盾しないかの裏付けに使える。

## 4. 判定基準

- **成功の目安**: 3回の計測いずれも、隠れ時間が目視で消失とわかるレベル(前回実測の158〜304ms)から明確に短縮され、`t10_design_delayed_resink.md` 9節が想定する「最後のSinkAllから次のSinkAllまでの最大ギャップである250ms以内」、理想的には最初の追い打ち(30ms後)でほぼ解消されている状態(1〜2フレーム=30ms程度以下)であること。
- **要再調査**: 3回のいずれかで、修正前と同程度(150ms超)の隠れ時間が計測された場合、または隠れ時間が0.25秒を上回る場合は、`ScheduleDelayedResink`/`ResinkTick` の遅延スケジュールが実機のProgman浮上タイミングに対して不十分である可能性があるため、t9/t10の前提(遅延スケジュール30/100/250/500ms)の見直しが必要になる。
- 併せて、修正前から変わらず保たれているべき点として、`t8_manual_check_steps.md` の1節(通常時にフェンスが他アプリの窓を隠さないこと)が本修正後も成立していることを目視で確認する(回帰確認)。
